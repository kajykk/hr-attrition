## 1. 引言

### 1.1 目的

本说明书定义 HRA（企业员工离职风险与人才流失预警系统）的功能、非功能需求与约束条件，作为设计、开发、测试、验收的基线。

### 1.2 范围

涵盖：用户认证、员工数据管理、多模态风险预测、预警生命周期、SHAP 可解释性、LLM 保留建议、人在回路、模型治理、合规审计、报表导出等全部功能。

不涵盖：薪酬计算、考勤打卡、招聘管理（由第三方 HR 系统承担）。

### 1.3 术语表

| 术语 | 含义 |
|---|---|
| HRA | HR Attrition Risk，本项目代号 |
| 离职风险分 | 0-100 分，越高表示离职概率越高 |
| 风险等级 | 5 档：低（<20）/中低（20-40）/中（40-60）/中高（60-80）/高（≥80）|
| SHAP | SHapley Additive exPlanations，模型可解释性方法 |
| 人在回路 | Human-in-the-Loop，模型预测后由人工复核 |
| Kill Switch | 一键关停，全局关闭预测服务 |
| RTM | Requirements Traceability Matrix 需求追踪矩阵 |
| PIPL | Personal Information Protection Law 个人信息保护法 |

### 1.4 参考资料

- HRA-D01 项目立项报告 V1.0
- DWS 系统架构文档（参考）

## 2. 总体描述

### 2.1 产品定位

HRA 是面向中型企业 HR 部门的员工保留预警 SaaS 平台，通过多模态 AI 模型提前 30-90 天识别高流失风险员工，提供可解释的预测结果与个性化保留建议。

### 2.2 用户类别画像

| 角色 | 权限范围 | 关键诉求 |
|---|---|---|
| HRBP | 查看本部门员工风险 + 申诉处理 + 干预记录 | 识别风险 + 执行保留 |
| HR 经理 | 全公司风险概览 + 部门画像 + 报表导出 | 战略决策 + 资源分配 |
| 直线经理 | 仅本团队风险概览（不显示具体员工）| 团队稳定性把控 |
| 管理员 | 系统配置 + 模型治理 + 审计日志 | 系统运维 + 合规 |
| 员工 | 数据权利行使（查询/导出/删除）| 隐私可控 |

### 2.3 运行环境

- 服务端：Linux x86_64 / Docker 24+ / Python 3.12
- 客户端：现代浏览器（Chrome 110+ / Edge 110+ / Safari 16+）
- 移动端：响应式 Web（暂不提供原生 App）

### 2.4 约束

- 多租户隔离：单实例支持多企业客户，数据物理或行级隔离
- 合规约束：PIPL + 欧盟 AI Act 高风险类别
- 算法约束：禁止使用性别/民族/政治面貌/宗教信仰/性取向/残疾状况作为模型特征；民族/残疾状况经员工单独同意采集（D04 加密存储），仅用于公平性审计，绝不入模型
- 语言约束：中文（默认）+ 英文（i18n 预留）
- 数据保留：预测记录 2 年，申诉记录 5 年

### 2.5 假设与依赖

- 假设：客户已具备基础 HR 系统，可提供员工花名册
- 依赖：OpenAI API（LLM 保留建议）
- 依赖：阿里云 OSS（员工数据备份）

## 4. 非功能需求（NFR）

### 4.1 性能

| 指标 | 目标值 | 测量方法 |
|---|---|---|
| HR 查询响应时间（缓存命中） | P99 < 1s | Locust 压测 |
| HR 查询响应时间（重新计算） | P99 < 5s | 同上 |
| 批量预测吞吐 | ≥ 5000 员工/小时 | Celery 任务监控 |
| LLM 建议首字延迟 | < 2s | SSE 监控 |
| 并发用户数 | 100 并发 | 压测 |
| 页面加载（LCP） | < 2.5s | Lighthouse |

### 4.2 可用性

- SLA：99.5%（单可用区部署，月度停机 < 3.6h）
- 计划停机：每月 1 次维护窗口（周日凌晨 02:00-04:00）
- 故障恢复：RTO < 1h，RPO < 1h

### 4.3 安全性

- 传输加密：TLS 1.3
- 存储加密：PII 字段 Fernet + 数据库 TDE
- 密码策略：长度 ≥ 12，含大小写+数字+特殊字符
- 限流：登录 5 次/分钟，API 100 次/分钟/用户
- OWASP Top10 全覆盖
- 等保 2.0 三级（SaaS 模式下由云厂商承担基础设施等保）

### 4.4 可维护性

- 代码覆盖率：≥ 80%
- MTTR：< 30min
- 文档完备性：D01-D11 + A01-A04 全部就绪
- 模块化：DWS 复用模块占比 ≥ 60%

### 4.5 可观测性

- 三支柱：Metrics（Prometheus）/ Logs（结构化 JSON）/ Traces（OpenTelemetry）
- 黄金信号：延迟/流量/错误/饱和度
- SLI/SLO：API 成功率 ≥ 99.5% / P99 < 1s
- 告警：分级（P0-P3）+ 升级策略

### 4.6 公平性与伦理

- 4 项公平性指标偏差 < 5%（性别/年龄/民族/disabled）
- 禁用特征列表：性别/民族/政治面貌/宗教信仰/性取向
- 伦理审查委员会：3 人组（HR + 法务 + 技术）
- 模型卡片（Model Card）公开披露

## 5. 数据需求

### 5.1 数据实体清单

| 实体 | 来源 | 保留期 | 敏感等级 |
|---|---|---|---|
| 员工档案 | 客户 HR 系统 | 离职后 2 年 | 高（PII） |
| 预测记录 | 系统生成 | 2 年 | 中 |
| 申诉记录 | 系统生成 | 5 年 | 中 |
| 干预记录 | HR 录入 | 5 年 | 中 |
| 审计日志 | 系统生成 | 5 年 | 高 |
| 模型版本 | 系统生成 | 永久 | 低 |
| 训练数据 | 客户授权 | 模型退役后 1 年 | 高（PII） |

### 5.2 数据流图

```
客户 HR 系统 ─CSV/Excel→ HRA ETL ─清洗→ 员工档案表
                                      ↓
                          特征工程 → 三模态预测
                                      ↓
                            风险分 + SHAP → 缓存
                                      ↓
                          HR 查询 ← WebSocket 推送
                                      ↓
                          申诉/标记 → 反馈库 → 再训练
```

### 5.3 数据保留策略

| 数据类型 | 保留期 | 到期处理 |
|---|---|---|
| 在职员工预测 | 2 年 | 自动归档 |
| 离职员工记录 | 离职后 2 年 | 物理删除（含 PII） |
| 申诉记录 | 5 年 | 物理删除 |
| 审计日志 | 5 年 | 物理删除 |
| 模型版本 | 永久 | 仅保留指标元数据 |
| 备份 | 30 天滚动覆盖 | - |

### 5.4 多模态合成数据策略

| 模态 | 生成方法 | 规模 | 标注 |
|---|---|---|---|
| 结构化 | SDV/CTGAN 基于 IBM HR 分布扩充 | 50000 条 | 自带标签 |
| 文本（OKR/360）| 通义千问按 SHAP 因子模板生成 | 5000 条 | 人工抽检 2k 条 |
| 行为时序 | 时序模拟器（结构化特征 + 在职月数 + 噪声）| 50000 条 | 自带标签 |

> 文本/行为合成数据用于补足 IBM HR 数据集缺失的模态，支撑 BERT 与 Isolation Forest 训练；合成方法与质量抽检规则见 D01 5.2、D08 T-301a/b。
