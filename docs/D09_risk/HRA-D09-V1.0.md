## 1. 风险管理方法论

### 1.1 风险识别方法

- 头脑风暴（团队）
- 德尔菲法（专家匿名）
- 检查表法（参考 PMBOK + ISO 31000）
- 历史项目复盘（DWS 经验）
- SWOT 分析

### 1.2 风险评估矩阵

**概率（5 级）**：

| 等级 | 概率 | 描述 |
|---|---|---|
| 5 | > 80% | 几乎肯定 |
| 4 | 60-80% | 很可能 |
| 3 | 30-60% | 可能 |
| 2 | 10-30% | 不太可能 |
| 1 | < 10% | 罕见 |

**影响（5 级）**：

| 等级 | 影响 | 描述 |
|---|---|---|
| 5 | 灾难性 | 项目失败/法律诉讼 |
| 4 | 严重 | 重大延期/成本超支 |
| 3 | 中等 | 局部延期/可修复 |
| 2 | 轻微 | 小幅影响 |
| 1 | 微不足道 | 可忽略 |

**风险值 = 概率 × 影响**（1-25）

| 风险值 | 等级 | 应对策略 |
|---|---|---|
| 15-25 | 红色（高）| 必须规避/转移 |
| 8-12 | 黄色（中）| 减轻 |
| 1-6 | 绿色（低）| 接受 + 监控 |

### 1.3 应对策略

- **规避**：调整计划消除风险
- **转移**：保险/外包/合同条款
- **减轻**：降低概率或影响
- **接受**：预留应急储备

## 3. 分类风险分析

### 3.1 技术风险

#### R03 模型效果不达预期

- **触发条件**：5 折交叉验证 AUC < 0.85
- **早期信号**：W3 模型训练阶段指标持续低于目标
- **应急预案**：
  1. 启动特征工程重构（增加交互特征）
  2. 尝试 XGBoost / CatBoost 替代 LightGBM
  3. 扩充合成数据规模至 100k
  4. 若仍不达标 → 降级为规则引擎 + 单模态
- **复盘机制**：W4 末评审，未达标触发预案

#### R07 LLM API 不稳定

- **触发条件**：OpenAI API 错误率 > 5% 或延迟 > 10s
- **早期信号**：监控告警 P0
- **应急预案**：
  1. 自动降级至规则模板建议
  2. 切换至备用 LLM（通义千问/Claude）
  3. 通知 HR 用户暂停 LLM 建议功能
- **复盘机制**：每周 LLM 调用成功率复盘

#### R12 模型漂移

- **触发条件**：PSI > 0.2 持续 3 天
- **早期信号**：drift_alerts 表持续告警
- **应急预案**：
  1. 触发再训练流水线
  2. 新模型金丝雀发布
  3. 若 72h 内无法收敛 → Kill Switch 暂停预测
- **复盘机制**：月度漂移复盘

### 3.2 数据风险

#### R11 LLM 调用泄露 PII

- **触发条件**：LLM prompt 中包含员工姓名/身份证号
- **早期信号**：审计日志检测到 PII
- **应急预案**：
  1. 立即下线 LLM 建议功能
  2. 排查 PII 脱敏模块
  3. 通知受影响员工（24h 内）
  4. 法务介入评估披露义务
- **复盘机制**：PII 脱敏单元测试每周执行

### 3.3 项目风险

#### R06 进度延期

- **触发条件**：关键路径任务超期 2 天以上
- **早期信号**：燃尽图偏离基线
- **应急预案**：
  1. 启用 PM 缓冲（30%）
  2. 砍掉 P2 需求（FR-EXPLAIN-004 反事实）
  3. 增加 AI 工具投入（更长上下文）
  4. 极端情况延期 1 周
- **复盘机制**：每周燃尽图复盘

#### R15 单人开发能力瓶颈

- **触发条件**：连续 3 天任务无进展
- **早期信号**：日站会报告阻塞
- **应急预案**：
  1. 调整任务优先级（聚焦 MVP）
  2. 求助 AI 工具（Claude Code 长上下文）
  3. 外包非核心模块（PDF 导出）
- **复盘机制**：每周自我评估

### 3.4 业务风险

#### R08 试点客户拒绝接入

- **触发条件**：M5 前 0 家客户接入
- **早期信号**：W4 客户沟通无响应
- **应急预案**：
  1. 启动备选客户名单（5 家）
  2. 提供免费 PoC 阶段（1 个月）
  3. 调整商业模式（按效果付费）
- **复盘机制**：每周客户跟进复盘

#### R22 商业模式验证失败

- **触发条件**：3 个月内付费客户 0
- **早期信号**：M8 验收时客户数 < 1
- **应急预案**：
  1. 转为开源项目（积累影响力）
  2. 调整定位为「HR 工具」而非「HR SaaS」
  3. 个人项目转为求职作品
- **复盘机制**：月度商业模式复盘

### 3.5 合规风险

#### R01 算法歧视

- **触发条件**：4 项公平性指标任一偏差 > 5%
- **早期信号**：公平性报告超标
- **应急预案**：
  1. 立即激活 Kill Switch
  2. 移除疑似歧视特征
  3. 模型再训练 + 公平性约束优化
  4. 伦理委员会审查
  5. 法务评估披露义务
- **复盘机制**：每月公平性报告

#### R20 跨境数据传输（已规避）

- **状态**：已通过 ADR-003 主选国内模型（通义千问 Max）规避，残余风险降至绿色
- **触发条件**：启用 OpenAI 备用路径且涉及员工 PII
- **早期信号**：法务审查发现 OpenAI 调用
- **应急预案**：
  1. 立即关闭 OpenAI 备用路径
  2. 切回国内 LLM（通义千问/DeepSeek）
  3. 严格 PII 脱敏（仅保留部门/岗位/职级）
  4. 数据出境安全评估（如已传输）
- **复盘机制**：季度法务复审

## 4. Top10 风险深度分析

### 4.1 R01 算法歧视（风险值 15，红色）

**深度分析**：
- 触发场景：模型对女性/少数民族/40+ 员工预测系统性偏高
- 根因可能：训练数据偏差 / 特征间接反映敏感属性（如岗位序列）
- 影响范围：法律诉讼 + 品牌损失 + 监管处罚（PIPL 罚款上限 5000 万或上年营业额 5%）
- 早期信号：
  - 公平性日报偏差 > 3%
  - HR 申诉中提及"歧视"
  - 媒体报道类似案例
- 应急预案（24h 内）：
  1. 激活 Kill Switch
  2. 伦理委员会紧急会议
  3. 法务评估披露义务
  4. 公关预案准备
- 长期改进：
  - 训练数据平衡采样
  - 公平性约束损失函数
  - 模型卡片公开披露

### 4.5 R09 公平性偏差超标（风险值 12）

**深度分析**：
- 触发场景：测试集上 4 项指标任一 > 5%
- 根因可能：训练数据样本不平衡 / 特征间接歧视
- 应急预案：
  1. W3 模型训练阶段发现 → 重采样 + 公平性约束
  2. W7 测试阶段发现 → 暂停上线 + 重新训练
  3. 上线后发现 → Kill Switch + 紧急修复

### 4.6 R10 需求蔓延（风险值 12）

**深度分析**：
- 触发场景：M2 后客户/自我持续追加需求
- 应急预案：
  1. 严格变更管理流程
  2. P2/P3 需求进入 V2.0 待办
  3. 周会评审需求优先级

### 4.7 R02 员工隐私诉讼（风险值 12）

**深度分析**：
- 触发场景：员工起诉公司未经同意使用个人数据
- 应急预案：
  1. 法务介入
  2. 提供 consent_records 作为证据
  3. 主动披露 + 整改
  4. 购买 E&O 保险（如有预算）

## 5. 风险监控机制

### 5.1 周度风险评审

- 频率：每周一 14:00 周例会
- 内容：风险登记册更新 + Top10 状态 + 新增风险
- 输出：风险周报

### 5.2 阈值告警

| 风险 ID | 监控指标 | 阈值 | 告警渠道 |

| R01 | 公平性偏差 | > 3% | 邮件 + 短信 |
| R03 | 模型 AUC | < 0.85 | 邮件 |
| R07 | LLM 错误率 | > 5% | 邮件 + IM |
| R09 | 公平性偏差 | > 5% | 短信 + Kill Switch |
