## 1. 变更管理流程

### 1.1 流程图

```
变更申请 → 评审（CAB）→ 实施 → 验证 → 归档
   │           │          │       │       │
   │           │          │       │       └─→ 更新本记录 + A01/A02/A03
   │           │          │       └─→ 测试通过 + 回归验证
   │           │          └─→ 按计划执行 + 灰度
   │           └─→ 标准变更预批准 / 常规变更 CAB 评审 / 紧急变更事后补审
   └─→ 提交变更申请单（CHANGE-REQ-NNN）
```

## 2. 变更分类

### 2.1 分类标准

| 类型 | 定义 | 审批流程 | 示例 |
|---|---|---|---|
| **标准变更** | 预批准的常规操作，低风险 | 免评审，记录即可 | 日常重启 / 配置微调 / 日志清理 |
| **常规变更** | 中等风险，影响业务功能 | CAB（变更顾问委员会）评审 | 新版本发布 / 数据库迁移 / 模型升级 |
| **紧急变更** | 高风险或紧急修复，事后补审 | 应急指挥批准，48h 内补 CAB | P0 故障 hotfix / 安全漏洞修复 |

### 2.2 CAB 组成

| 角色 | 姓名 | 职责 |
|---|---|---|
| CAB 主席 | 邝振华 | 变更审批 |
| 运维代表 | ____ | 影响评估 |
| 开发代表 | 邝振华 | 技术评审 |
| 业务代表 | ____ | 业务影响 |

### 2.3 评审标准

| 维度 | 评估项 |
|---|---|
| 影响 | 影响用户数 / 功能范围 / 数据完整性 |
| 风险 | 回滚难度 / 数据丢失风险 / 合规风险 |
| 时机 | 是否业务低峰期 / 是否提前通知 |
| 验证 | 测试覆盖 / 灰度方案 / 回滚预案 |

## 4. 回滚程序

### 4.1 通用回滚原则

- 每个变更必须预设回滚方案
- 回滚操作优先于根因排查（P0/P1 优先恢复服务）
- 回滚后 24h 内编写事件报告

### 4.2 各类变更回滚步骤

#### 4.2.1 代码发布回滚

```bash
# 1. 回滚到上一版本镜像
docker compose down api worker
docker tag hra-api:v1.0 hra-api:rollback
docker compose up -d api worker

# 2. 验证健康
curl -s http://localhost:8000/health | jq .status
# 期望：healthy

# 3. Git 回滚（如需）
git revert <commit-sha>
```

#### 4.2.2 数据库迁移回滚

```bash
cd backend
# 查看当前版本
alembic current
# 回滚上一版本
alembic downgrade -1
# 验证 schema
psql -c "\dt"
```

**注意**：涉及数据删除的迁移不可回滚（如 DROP COLUMN），需从备份恢复（见 A01 Runbook 2 §2.3）。

#### 4.2.3 模型版本回滚

见 A03 §5 自动回滚流程。手动回滚：

```bash
# 1. 激活 Kill Switch（防止回滚期间误用）
curl -X POST http://localhost:8000/api/v1/admin/kill-switch/activate -d '{"reason":"模型手动回滚"}'

# 2. 切换工件
cd backend
cp app/ml/models/structured_lgbm.pkl.bak app/ml/models/structured_lgbm.pkl
cp app/ml/models/behavior_if.pkl.bak app/ml/models/behavior_if.pkl

# 3. 更新 model_versions 状态
psql -c "UPDATE model_versions SET status='active' WHERE version='fusion-engine-v1';"
psql -c "UPDATE model_versions SET status='rolled_back' WHERE version='fusion-engine-v2';"

# 4. 重启 api/worker 加载旧模型
docker compose restart api worker

# 5. 验证
curl -s http://localhost:8000/api/v1/admin/model-version | jq .version
# 期望：fusion-engine-v1

# 6. 解除 Kill Switch
curl -X POST http://localhost:8000/api/v1/admin/kill-switch/deactivate
```

#### 4.2.4 配置变更回滚

```bash
# .env 回滚（Git 版本控制）
git checkout HEAD~1 -- .env
docker compose up -d api worker

# 或使用 .env.bak
cp .env.bak .env
docker compose up -d api worker
```

#### 4.2.5 LLM 模型切换回滚

```bash
# 修改 .env 的 LLM_PRIMARY 回退
# 原：LLM_PRIMARY=deepseek-v3
# 改：LLM_PRIMARY=qwen-max
docker compose up -d api
```
